# 珞珈生化智能体架构与运行说明

## 主链路

学生主链路固定为八步文字实验：任务与原理 → 知识检验 → 分步文字推演 → 提交与点评 → Gate检查。学生不执行真实实验。普通提问调用`WF-TEXT/tutor_question`，只保存对话；正式提交调用`WF-TEXT/evaluate`，服务端先校验结构，再用确定性Gate覆盖模型结论，最后通过数据库函数原子保存回答版本、评阅、步骤状态和超星待同步事件。

同一个智能体按服务端能力进入学生或教师工作区。教师模式不让模型计算人数；服务端按授权班级查询 Supabase，确定性计算进度、高频遗漏和待复核记录。教师可进入学习体验会话（`agent_role='teacher'`），该模式的评价由服务端直写（不经学生评阅 RPC、不入 `sync_outbox`），不进入学生成绩、班级统计与超星同步。

## 数据规则

- 一次八步学习对应一个 `agent_session`，`agent_role` 区分正式学生（`student`）与教师体验（`teacher`）；所有统计查询显式限定 `agent_role`。
- 学生开会话时写入 `agent_messages` 的 `content_snapshot` 消息（metadata 存 content_version_id 与 source_hash），会话终身读取该快照对应的 `content_versions` 版本，后续发布不改变历史报告和成绩。
- `agent_messages`和`step_attempts`只新增、不覆盖。
- 当前步骤由服务端数据库函数推进，不能通过URL跳步。
- 第三次正式修改后，一般遗漏转为`teacher_review`；安全或原理Gate仍须修正。
- 学生只读取自己的消息、图片和报告；教师只能读取授权班级。
- 完整rubric和知识块不向学生RLS开放。

## 接口

学生：

- `POST /api/student/session`：创建或恢复八步会话。
- `POST /api/student/messages`：普通提问，不计正式次数。
- `POST /api/student/evaluate`：正式提交并评阅。
- `POST /api/student/image-question`：把当前步骤图片题插入对话。
- `POST /api/student/media/upload`：兼容接口，申请私有签名上传；不在当前学生主界面暴露。
- `POST /api/student/media/evaluate`：兼容接口，登记图片并调用视觉工作流；课程案例图学习优先使用老师提供的素材。
- `POST /api/student/report`：生成或读取学习情况报告。
- `GET /api/student/content`：按会话读取固定版本课程内容。
- `GET|POST /api/student/grade`：读取过程成绩或提交一次成绩异议。

教师：

- `POST /api/teacher/session`：创建教师智能体会话。
- `POST /api/teacher/query`：查询真实学习记录和证据。
- `POST /api/teacher/reviews`：保存复核结论或补充意见。
- `GET|POST /api/teacher/practice-session`：创建或恢复教师独立学习体验。
- `GET|PUT /api/teacher/content`、`POST /api/teacher/content/publish`、`POST /api/teacher/content/assets`：版本化内容与素材管理。
- `GET|POST /api/teacher/grade-reviews`：成绩异议查询与最终认定。

内部：

- `POST /api/internal/sync-chaoxing`：使用Worker Secret处理超星outbox。
- `GET /api/internal/chaoxing-health`：使用Worker Secret检查超星传输配置和可选回查地址；不执行写入。

所有接口返回`{ok,data,requestId}`或`{ok:false,error,requestId}`。

## 上线顺序

1. 在Coze实例化 Supabase 并按文件名顺序执行三份迁移。
2. 配置Service Role，仅供服务端使用。
3. 运行`pnpm seed:content`。
4. 创建三个Coze工作流并配置ID、Token。
5. 用演示学生和演示教师完成验收。
6. 上传并部署Coze项目，取得HTTPS域名。
7. 配置校方角色 ID、在超星登记正式回调，通过回读校验后启用 OAuth 并关闭演示入口。
8. 获得表单正式外部接口或已发布任务流契约后配置`CHAOXING_FORM_TRANSPORT`、同步URL、Token、限流和可选回查地址。

## 尚需外部配置才能验证的能力

- Supabase远程迁移与真实RLS：需要Coze实例化后的项目凭据。
- 三个Coze工作流真实运行：需要工作流ID和服务端Token。
- 超星OAuth：需要APPID、APPKEY、武汉大学FID及已登记回调域名。
- 超星表单写入：需要学校提供正式外部调用URL或已发布任务流调用契约、鉴权、限流和回查规则；浏览器内部请求不作为生产接口。
# 页面与交互层级

- 学生地图：`/student/map`；学生步骤：`/student/step/[stepId]`；学习报告：`/student/report`。
- 教师端采用任务分层路由：`/teacher/dashboard` 教学概览、`/teacher/students` 学生管理、`/teacher/reviews` 成绩复核、`/teacher/content` 内容管理。
- 学习通登录同步 `profiles.major_name / grade_name / class_name`；教师概览接口返回可筛选维度集合。提供方未返回的字段归入“待同步”，不根据姓名或单位名推断。
- UI 预览使用相同层级：`/preview/student/map`、`/preview/student/step/[stepId]`、`/preview/student/report`、`/preview/teacher/dashboard`。
- 核心流程使用独立页面；游客选择、首次指引、提示与求助使用轻量抽屉或内联反馈。移动抽屉支持下滑关闭，桌面弹窗支持遮罩关闭。
- 学生端会预取地图、报告及已解锁步骤；所有流程页面保留上一阶段、下一阶段和返回首页入口。
