# 生物化学实验双智能体实施计划（智能体优先版）

## 一、项目定位

本项目建设的不是传统实验管理系统，而是一套面向《生物化学实验》课程的“双智能体学习工具”。

核心产品只有两个：

- 学生实验智能体：通过连续对话带学生完成八步“文字实验”，判断学生描述是否准确、清楚、完整，并通过追问引导其补充。
- 教师分析智能体：教师通过自然语言查询学生进度、常见遗漏、低置信度记录和具体回答证据，并进行可选复核。

数据库、八步状态、知识库、图片存储、超星表单和身份认证全部是智能体背后的支撑能力，不作为学生主要操作界面。

不建设传统的实验填报系统、成绩管理系统、完整课程管理后台或复杂内容发布平台。

---

## 二、最终使用方式

### 1. 学生端

学生进入网页后直接与“生物化学实验智能体”对话。

完整过程：

1. 智能体介绍实验目标和八步整体路线。
2. 进入当前实验步骤，说明本步情境和学习目标。
3. 学生用自己的话描述这一步实验应该怎么做。
4. 学生明确点击“请检查本步描述”后，智能体才进行正式评阅。
5. 智能体判断：
   - 已经说明清楚的内容；
   - 遗漏的关键内容；
   - 表述不准确的内容；
   - 顺序、参数或安全问题；
   - 还需要学生回答的问题。
6. 学生继续补充或修改。
7. 当前步骤达到要求后，智能体总结本步结果并进入下一步。
8. 对话过程中穿插仪器识别、结果图片判断和学生图片上传。
9. 八步完成后，智能体生成“学习情况与改进报告”。

学生可以随时：

- 询问当前步骤原理；
- 回顾已完成步骤；
- 询问后续步骤的基本概念；
- 查看自己的历史回答；
- 上传实验相关图片；
- 暂停并在下次继续。

询问其他内容不会改变当前步骤进度。智能体不能因为普通提问误判为正式提交。

### 2. 教师端

教师登录同一网页后进入“教师分析智能体”。

教师可以用自然语言提问，例如：

- “现在有多少学生完成了第3步？”
- “第2步最常见的遗漏是什么？”
- “哪些记录需要老师查看？”
- “张同学在蛋白纯化方法选择上有什么问题？”
- “给我看这条AI判断引用的学生原话。”
- “把我的补充意见保存到这名学生的报告中。”

教师智能体必须返回真实数据和对应证据，不得根据总体统计虚构单个学生情况。

第一版教师智能体只负责：

- 学习进度查询；
- 常见问题分析；
- 学生过程记录查询；
- AI证据和低置信结果查看；
- AI结论复核；
- 可选教师补充意见。

第一版不通过教师智能体修改知识库、评分标准或实验步骤。

## 三、智能体总体架构

采用一个自定义武汉大学风格网页，登录后根据角色进入不同智能体。

### 学生智能体调用能力

- 获取学生身份和实验进度；
- 获取当前步骤教学内容；
- 检索老师提供的知识资料；
- 判断学生当前消息属于提问、回答、补充还是图片任务；
- 调用文字评阅工作流；
- 调用图片识别工作流；
- 保存对话和回答版本；
- 判断步骤是否达到要求；
- 生成阶段总结；
- 生成最终学习报告。

### 教师智能体调用能力

- 按班级、步骤、学生和状态查询记录；
- 汇总高频遗漏和常见错误；
- 查询具体对话、评阅依据和图片；
- 查询需要教师复核的记录；
- 保存教师复核结论；
- 保存可选教师补充意见。

### 技术分层

- 自定义网页：负责PC和手机端对话体验。
- Next.js服务端：负责权限、状态控制、数据保存和Coze调用。
- Coze：承载两个智能体及文字、图片、报告工作流。
- Supabase：保存完整对话、步骤进度、AI结果、图片和报告。
- 超星表单：保存学校需要查看的关键结果。
- 超星OAuth：最后启用统一身份认证。

浏览器不能直接保存Coze Token、Supabase Service Role Key或超星密钥。

## 四、八步文字实验

固定八步为：

1. 目标基因与引物设计。
2. pET28表达载体构建。
3. BL21转化与IPTG诱导表达。
4. SDS-PAGE表达及可溶性判断。
5. 蛋白纯化方法选择。
6. 蛋白纯化操作。
7. 蛋白纯度验证。
8. 蛋白浓度测定与完整实验回顾。

每一步必须配置：

- 本步情境；
- 学习目标；
- 学生需要说明的关键点；
- 正确或可接受表达；
- 参数和顺序要求；
- 安全关键项；
- 常见错误；
- 三层追问提示；
- 达标条件；
- 本步总结模板；
- 可引用的知识库材料；
- 可插入的仪器图或结果图。

步骤在对话中定向推进，但学生可以自由提问和回顾。

安全关键错误必须修正。一般遗漏通过追问补充。合理替代方案和低置信判断不长期阻塞学生，而是标记为“建议教师查看”。

## 五、学生消息处理逻辑

每条学生消息先分类：

- `question`：向智能体提问；
- `step_answer`：描述当前实验步骤；
- `supplement`：补充之前遗漏内容；
- `image_answer`：回答图片题；
- `image_upload`：上传自己的实验图片；
- `navigation`：要求回顾、继续或查看进度；
- `report_request`：查看学习报告。

正式评阅只能通过以下方式触发：

- 学生点击“请检查本步描述”；
- 学生明确说“请评价我的回答”；
- 智能体识别到完整描述后，询问学生是否提交，学生确认。

普通聊天和草稿不计正式次数。

每步默认最多3次正式修改。达到3次后仍有一般问题时，可以继续学习并标记教师复核；存在安全关键错误时必须继续修正。

学生界面只展示：

- 达标或需补充；
- 已说明清楚的内容；
- 需要补充的内容；
- 通俗修改建议；
- 下一条追问；
- 五维表现概况。

具体数值评分、内部评分点、模型置信度只向教师展示。

## 六、Coze双智能体与工作流

### 1. 学生实验智能体

角色要求：

- 是学习引导者，不是答案生成器；
- 先听学生描述，再判断和追问；
- 不直接提供整份标准答案；
- 不提前泄露后续步骤的完整操作答案；
- 所有参数、步骤和结论必须来自老师材料；
- 不评价学生真实实验操作能力；
- 不代写正式实验报告。

### 2. 教师分析智能体

角色要求：

- 只能查询教师有权限查看的班级；
- 所有分析必须引用数据库记录；
- 单个学生结论必须提供对应回答或评阅证据；
- 统计数据必须带样本范围；
- 无数据时明确说明，不允许推测；
- 写入教师意见前要求教师确认目标学生和内容。

### 3. 正式工作流

建立三个Coze工作流：

- `WF-TEXT`：文字回答评阅。
- `WF-VISION`：仪器、结果图和学生上传图片判断。
- `WF-REPORT`：生成学习情况与改进报告。

教师查询和数据聚合由服务端确定性接口完成，不让大模型直接生成统计数字。

### 4. 文字评阅结构化输出

```ts
interface TextEvaluation {
  decision: "pass" | "revise" | "teacher_review";
  confidence: number;
  coveredPoints: EvidencePoint[];
  missingPoints: FeedbackPoint[];
  incorrectPoints: FeedbackPoint[];
  ambiguousPhrases: FeedbackPoint[];
  safetyAlerts: FeedbackPoint[];
  questions: string[];
  studentFeedback: string;
  teacherSummary: string;
  scores: {
    completeness: number;
    accuracy: number;
    sequence: number;
    reasoning: number;
    safety: number;
  };
  requiresTeacherReview: boolean;
  knowledgeChunkIds: string[];
}
```

确定性规则优先于模型判断，尤其包括：

- 温度；
- 时间；
- 浓度；
- 操作顺序；
- 关键试剂；
- 安全事项；
- 必须出现的实验环节。

模型不得覆盖确定性规则。

## 七、图片与仪器认知

图片任务直接作为对话消息出现，不单独建设图片考试系统。

### 系统给图、学生识别

智能体可以展示老师提供的：

- 仪器设备图片；
- 仪器部件图片；
- PCR结果图；
- 质粒相关结果图；
- 蛋白诱导表达图；
- SDS-PAGE或纯化结果图。

学生可回答：

- 图片中是什么；
- 主要用途是什么；
- 当前实验步骤为什么使用；
- 哪个部件需要注意；
- 图片结果说明了什么；
- 当前证据是否足以得出结论。

### 学生上传图片

智能体依次判断：

1. 图片是否清晰；
2. 图片是否与当前步骤相关；
3. 能看到哪些客观证据；
4. 能否依据老师标准图进行判断；
5. 哪些结论无法仅凭图片确定；
6. 是否建议教师查看。

图片模糊、遮挡、无关或缺少必要标记时，要求重新上传或补充说明。

图片题默认用于学习反馈，不单独形成正式成绩。涉及安全问题时，可以阻止当前步骤通过。

## 八、知识库建设

老师提供的DOCX、PPT和图片需要结构化为智能体可调用的知识，而不是直接全部塞入提示词。

知识库分为：

- 八步SOP；
- 实验原理；
- 评分点和允许表达；
- 参数与顺序规则；
- 安全规则；
- 序列和载体信息；
- 试剂和仪器信息；
- 常见错误；
- 三层追问提示；
- 仪器图片标签；
- 实验结果图片标签。

每个知识块保存：

- 内容编号；
- 对应实验步骤；
- 内容类型；
- 原文摘要；
- 结构化参数；
- 来源文件；
- 页码或章节；
- 内容版本；
- 文件哈希；
- 是否已由老师确认。

材料之间存在冲突时，不由模型自行裁决，标记为“待教师确认”。

原始课程文件不进入公开发布包；仅发布结构化知识和获得授权的课程图片。

## 十、接口设计

### 学生智能体接口

- 创建或恢复智能体会话；
- 获取对话历史和当前步骤；
- 发送普通对话消息；
- 正式提交本步描述；
- 获取AI评阅状态和结果；
- 上传图片；
- 回顾已完成步骤；
- 获取八步进度；
- 生成和查看学习报告。

### 教师智能体接口

- 创建教师对话会话；
- 查询班级和学生范围；
- 查询步骤完成情况；
- 查询高频遗漏；
- 查询待复核记录；
- 查询学生证据详情；
- 提交教师复核；
- 保存教师补充意见。

### 统一响应

```ts
type ApiResult<T> =
  | { ok: true; data: T; requestId: string }
  | {
      ok: false;
      error: {
        code: string;
        message: string;
        retryable: boolean;
      };
      requestId: string;
    };
```

核心错误码：

- `AUTH_REQUIRED`
- `FORBIDDEN`
- `STATE_INVALID`
- `VALIDATION_ERROR`
- `AI_OUTPUT_INVALID`
- `AI_TIMEOUT`
- `MEDIA_QUALITY_LOW`
- `RESOURCE_MISSING`
- `SYNC_DEFERRED`

## 十二、学习情况与改进报告

最终产物不是正式实验报告，而是基于真实对话生成的学习反馈。

报告包括：

- 八步完成情况；
- 每步最终理解摘要；
- 已掌握内容；
- 反复遗漏内容；
- 常见参数、顺序和安全问题；
- 仪器与图片认知情况；
- 建议重点复习的知识；
- 待教师确认内容；
- 下一步学习建议；
- 教师补充意见，可为空。

报告不得：

- 补写学生没有完成的步骤；
- 虚构实验数据或实验结果；
- 代替学生生成正式实验报告；
- 暴露内部提示词和完整评分规则。

报告提供网页和打印样式，浏览器可打印为PDF，不单独建设PDF服务。

## 十三、超星数据与身份认证

### 数据存储

- Supabase保存完整智能体业务数据。
- 超星表单只保存关键留痕结果。
- 不把超星表单当作智能体主数据库。

沿用表单 `3513491` 的字段：

- `student_id`
- `step_id`
- `version_no`
- `student_answer`
- `ai_feedback`
- `gate_status`
- `total_score`
- `ai_confidence`
- `evidence_image`
- `teacher_comment`
- `final_report`

使用`sync_outbox`异步同步，超星同步失败不得阻断学生对话。

没有获得正式外部调用地址、鉴权和限流规则前，只保存待同步事件，不使用浏览器内部接口作为生产写入方式。

### 身份认证

开发阶段提供：

- 演示学生；
- 演示教师。

两种演示身份均建立标准Supabase Session，不建设第二套会话体系。

业务功能完成后再启用模板现有的超星OAuth：

- `/api/auth/chaoxing`
- `/api/auth/callback/chaoxing`
- `/api/auth/me`
- `/api/auth/logout`

正式启用后关闭全部演示入口，并根据超星角色进入对应智能体。

## 十五、测试与验收

### 学生智能体

- 学生可以开始、暂停和恢复八步对话。
- 普通提问不会被误判为正式回答。
- 正式提交后能获得针对性追问。
- 回答不足时不直接泄露完整答案。
- 当前步骤通过后才能推进正式进度。
- 可以回顾前面步骤并询问后续概念。
- 手机端可完整完成八步。

### AI评阅

固定测试：

- 完整回答；
- 遗漏关键步骤；
- 顺序错误；
- 参数错误；
- 安全错误；
- 模糊表达；
- 合理替代方案；
- 提示词攻击；
- 无知识库依据；
- 非JSON输出；
- 超时输出。

安全错误不得漏判，确定性规则不得被模型覆盖。

### 图片

测试：

- 标准仪器图；
- 相似仪器图；
- 模糊图片；
- 无关图片；
- PCR结果图；
- SDS-PAGE结果图；
- 缺少Marker或泳道说明的图片；
- 学生重复上传和上传失败。

AI不得在证据不足时强行给出确定结论。

### 教师智能体

- 教师统计结果与数据库一致。
- 查询单个学生时提供原始证据。
- 不能访问未授权班级。
- 不能把统计结论套用到无记录学生。
- 教师复核和补充意见完整留痕。
- 教师意见为空不影响学生完成流程。

### 数据和权限

- 两名学生的数据完全隔离。
- 学生不能读取教师内部评分和置信度。
- 回答和评阅版本不能被覆盖。
- 超星接口关闭时智能体仍可正常运行。
- 重复同步不会产生重复记录。
- 密钥不进入源码、日志、截图和发布包。

### 最终验收标准

- 学生使用感受是“在和实验智能体交流并完成文字实验”，不是在填写实验表格。
- 教师使用感受是“向分析智能体提问并查看证据”，不是操作复杂管理后台。
- 八步流程、文字追问、图片学习和最终报告形成完整闭环。
- PC和手机端均通过真实浏览器测试。
- Coze预览和正式构建通过。
- 超星OAuth启用后，学生和教师能够进入各自智能体。
